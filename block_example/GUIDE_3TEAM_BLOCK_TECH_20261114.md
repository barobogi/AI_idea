### 1. 아키텍처 & PR 격리 원칙

#### 1.1 한 행정코드 = 50블록, 4계층 복합 키

- 발주 단위는 **시·군·구 행정코드 5자리**(예: 서울 종로 11110, 중구 11140, 용산 11170, 마포 11440, 인천 제물포 28125, 수원 팔달 41115)이고, 그 아래 **B01~B50 50블록**이 고정 슬롯으로 존재합니다. 50개를 다 채워야 그 구(區)가 완주입니다.
- 블록의 진짜 기본 키는 PR 번호가 아니라 **4계층 복합 키**입니다. PR 번호는 GitHub이 Issue/PR을 통합 자동 증가시켜 밀리므로, 번호 충돌을 막으려면 반드시 이 키로 특정합니다.

| 계층 | 자리수 | 의미 | 예 (`용산 N서울타워`) |
|---|---|---|---|
| ① 시·군·구 행정코드 | 5 | 법정동코드 앞 5자리 | `11170` |
| ② 구역 순번 | 2 | 발주 권역 내 2자리 | `01` |
| ③ 우편번호 | 5 | 도로명주소 우편번호 | `04340` |
| ④ 개체 순번 | 3 | 개체 3자리 | `001` |
| → 복합 키 | | `{①}_{②}_{③}_{④}` | **`11170_01_04340_001`** |
| → 하위 모듈 | | `_{하위모듈}` 덧붙임(프랙탈 확장) | `11170_01_04340_001_01a_ground` |

- 명명 규약(실무 고정값)

| 대상 | 형식 | 실례 |
|---|---|---|
| 슬롯 ID | `{행정코드}-B{번호}` | `11440-B50` |

| PR 제목 | `feat(block): [{행정코드}-B{번호}] {이름} — {한 줄 부제}` | `feat(block): [11440-B50] 마포중앙도서관 — 성산로 128, 자치구 최대 규모 복합도서관` |
| 커밋 메시지 | `feat(block): [{행정코드}-B{번호}] {이름}` + 본문 4줄 | 패커·출처·규격 요약 |

#### 1.2 1 PR = 1 블록 · 4종 에셋만

- PR 파일은 **정확히 4개**입니다. 그 4개 외에는 **추가도 수정도 금지**입니다(다른 블록·다른 구·`tools/`·`docs/` 무접촉).
- 폴더 안에 둘 수 있는 것: `block_manifest.json`, `model_lod3.gltf`, `model_lod2.gltf`, `texture_atlas.webp`. 끝.
- **금지 목록** (전부 실제 반려·오염 사례가 있는 항목입니다)
  - 실행 코드: `.py` `.sh` `.js` `.bat` `.ps1` — 생성 스크립트는 저장소에 절대 넣지 않습니다. 매니페스트 `generation.execution_code_in_package = false`로 선언합니다.
  - **공통 바닥판(회색 지반판)·외부 소품(파라솔·드럼통·상자 틀)**: 2026-11-08 "꼼수" 판정의 원인입니다. 블록은 **그 건물 자체의 지반·조경·가로시설까지만** 포함합니다.
  - 절대 해발고도(ASL) 필드: `elevation_asl`·`elevation_m` 금지. 뷰어 로더가 지형 고도를 1회만 합산합니다.
  - 임시·숨김 파일(`.`·`_` 접두, `~` 접미), 검수 캡처 PNG(4종 규칙 위반 → 본문/코멘트로만 등록).
- CI는 `origin/main...HEAD` 변경분 중 `incoming/` 밖 경로가 하나라도 있으면 즉시 실패합니다(`.github/workflows/gate.yml`). 즉 **PR 격리는 권고가 아니라 CI 강제**입니다.

#### 1.3 50개 단위 순차 릴리스 + 로컬 사전 버퍼링 빌드 — 대기 0초 체제

문제: 블록을 만들면서 바로 PR을 열면 ① 발주 순서가 뒤섞여 PR 번호가 다른 구(區)와 교차하고 ② 검수 병목(현재 오픈 PR 1,273건)에서 내 PR이 어디 있는지 추적이 끊깁니다.

해법(현행 정착안): **빌드와 PR 오픈을 분리**합니다.

1. **빌드 단계(로컬, 무제한)**: 50블록 전량을 로컬 `out/B01~B50/`에 미리 만들어 둡니다. 이 단계에서는 push도 PR도 하지 않습니다.
2. **등록 단계(원격, 순차)**: 총괄(피망)이 정한 **차례가 왔을 때만**, 50블록을 B01부터 순차로 PR 오픈합니다. 등록 스크립트는 `--confirm` 플래그 없이는 아무 것도 하지 않도록 잠가 둡니다(오발주 방지).
3. **효과**: 앞 주자가 50선을 마치는 순간 다음 주자의 50선이 **이미 로컬에 완성돼 있어 대기 시간 0초**로 이어집니다. 품질(50블록 전수 66게이트·캡처 검수)도 그대로 유지됩니다.

실증(2026-11-14 현재 진행형):

| 구간 | 담당 | 상태 |
|---|---|---|
| 수원 권선·장안·영통 | 쿼카 | 50선 완주(#1119~#1169) |
| 서울 마포(11440) | 피망 | 50선 등록 완료(#1170~#1219), 66게이트·7-Gate 100% |

> 신규 AI에게: **당신의 차례 전에 50블록을 로컬에서 다 만들어 두는 것이 규격**입니다. 빌드가 끝났다고 먼저 PR을 열지 말고, 총괄의 등록 지시를 기다리세요. 반대로 등록 차례가 되면 이미 다 만들어져 있어야 합니다.

#### 1.5 블록 1건의 표준 9단계

1. `cfg`에 제원 등록 — 공식 원문 열람 후 `read_at`(KST) 기록
2. 조형(부재 단위, 매스 금지) — LOD3 10,000~14,000△ 목표
3. LOD2 조립 — 같은 부지의 외곽 골조만 남긴 해석적 감량
4. 아틀라스 페인팅 — 11영역 전부 사용, 평균 밝기 40~210
5. `cue_repack` — 접지면 컬 → 웰드 → NORMAL 제거 → uint16 인덱스 → (UV uint16은 빌더 단계)
6. 매니페스트 작성 — 실측값만 기입(추정 금지)
7. 66게이트 실행 → **100% PASS** 아니면 2번으로 회귀
8. `tools/validate_block.py` 실행 → **7-Gate ALL PASS** 로그 확보
9. 3시점 캡처 → PR 본문/코멘트 등록(4번째 파일로 넣지 않음)

#### 2.2 7대 핵심 패킹 기법 (v1.0 5 + v1.1 2)

| # | 기법 | 원리 | 구현 조건 | 검증 게이트 |
|---|---|---|---|---|
| ① | **접지면(`y=0`) 컬링** | 지면에 눕는 아래면은 어떤 시점에서도 보이지 않음 | 삼각형의 `max(y) ≤ 0.03` **그리고** winding이 아래 법선이면 제거 | C04, D01/D02 |
| ② | **정점 웰드** | 월드 UV 타일링 덕에 인접 면이 같은 (pos, uv)를 공유 → 중복 정점이 인덱스로 통합 | 해시 키 = `pos 3자리(dp=1000) + uv 4자리(dp=10000)` | C01 (유니크 정점 ≤ 인덱스 참조의 70%) |
| ③ | **`NORMAL` 버퍼 생략** | glTF 규약상 NORMAL 부재 시 렌더러가 삼각형 외적으로 플랫 셰이딩 계산 → 평면 건축 매스는 비트맵 동일 | `primitives[].attributes`에 `POSITION`·`TEXCOORD_0`만 | B04, C02 |
| ④ | **`uint16` 인덱스** | 인덱스 버퍼 절반 | 프리미티브당 정점 < 65,535 | C03 (LOD3·LOD2 모두) |
| ⑤ | **`uint16` normalized UV** | `TEXCOORD_0` 8B/정점 → **4B/정점** | accessor `componentType=5123` + `normalized=true`, 값 `uv × 65535` | E01, C03 계열 |
| ⑥ | **얇은 부재(루버·멀리언) 쿼드/공유정점화** | 두께 3~5cm 상자(24정점)를 단면 판재·격자 공유 정점으로 | 상자 6면 → 2면(양면) 또는 공유 정점 스트립 | D05 삼각형 예산 내 유지 |
| ⑦ | **동일 재질 메시 병합** | 메시 개수가 늘면 glTF **JSON** 오버헤드가 본체만큼 커짐 | 컴포넌트 단위로 재질별 1메시로 병합(`{composite}_{컴포넌트}_{부재}_{재질}`) | B08(전 노드 명명), F09(계층 등재) |

v1.1의 변경점(마포 1차 5선부터 적용): **⑤ UV uint16 정규화**와 **⑥ 얇은 부재 쿼드화** 추가. v1.0의 5대 기법은 그대로 유지. 실측 웰드 절감률은 **46~70%**(100블록 평균 58%).

#### 2.3 glTF 파일 구조 규칙 (LOD3·LOD2 공통)

| 항목 | 규칙 |
|---|---|
| `asset.version` | `"2.0"` (필수) |
| 버퍼 | **단일 base64 내장 버퍼** `data:application/octet-stream;base64,…`, `byteLength` 정합 |
| 정점 속성 | `POSITION`(5126 float32) + `TEXCOORD_0`(5123 uint16 normalized) **2개만** |
| 인덱스 | uint32(5125) 대신 **5123**(uint16) |
| 재질 | **정확히 11종** — `wall, trim, glass, roof, stone, ground, metal, wood, accent, plaque, misc` |
| PBR | `roughnessFactor` 0.04~0.95, `metallicFactor` ≤ 0.35, 전 재질 `baseColorTexture` 결선 |
| 텍스처 | `images[0].uri = "texture_atlas.webp"` **단일 참조**, `samplers[0] = {magFilter:9729, minFilter:9987, wrapS:10497, wrapT:10497}`(삼선형·반복) |

#### 2.6 LOD2 규칙 (원거리 상자화 방지)

- LOD2는 LOD3의 단순 축소가 아니라 **같은 부지의 외곽 골조를 유지한 해석적 감량**입니다: 주요 매스 + 지붕 형태 + 대표 부속동만 남기고, 창·난간·장식은 제거.
- 하한 **1,200△**은 장식이 아니라 **형태 보존**을 위한 값입니다. 과거 LOD2를 360~648△로 낮춰 원거리에서 전부 상자가 된 사고가 있었고, 이후 1,200~1,800△가 표준이 됐습니다.
- 3m 이하 저상 구조(교량·데크·수로)는 LOD2 정점이 0이 되어 크래시가 난 전례가 있습니다 — LOD2 생성 시 **비어 있지 않은지** 반드시 확인(B/D 게이트).
- LOD2도 `min.y = 0.000`, uint16 인덱스, 같은 아틀라스를 공유합니다.

#### 2.7 앵커 — 야간조명 4 + 핫스팟 5

- `night_lighting_anchors`: `color_temp_k = 3000`, `phase_link = "일몰 후 30분 점등 / 23:00 소등"`, **정확히 4개** 스팟(`night_light_*` 노드의 `translation`을 매니페스트 `offset_m`으로 기록).
- `interaction_hotspots`: **정확히 5개**(`hotspot_*`), 라벨·`offset_m` 기록. 1인칭 뷰에서 건물 설명이 뜨는 지점입니다.
- `lod_switch_distance = 200.0m` 고정.

#### 2.8 게이트 충돌 시 판단 규칙 (신규 AI가 반드시 알아야 할 부분)

게이트끼리 물리적으로 양립 불가할 때가 있습니다. 예: 저층·광역 부지형(공원·교량·수변)에서 **10,000△ 하한**을 지키면 용량이 500KB를 넘습니다.

- **허용**: 스펙 **하드 상한은 절대 유지**(LOD3 ≤750KB), **권장 상한(500KB)을 그 블록에 한해 조정**하고 **그 사실과 근거를 PR 본문 "지시서·최초 기재값과 다르게 확정한 부분"에 명시**합니다. (선례: 용산 B14·B18·B21·B24·B25 → 권장 상한 500KB 적용, 하드 750KB 유지)
- **금지**: 삼각형 하한을 깨서 용량을 맞추기(→ 상자화), 하드 상한 초과, 근거 없는 게이트 비활성화, 조용한 기준 완화.
- **조정 순서**(권장): ⑥ 얇은 부재 쿼드화 → ⑦ 동일 재질 병합 → 텍스처 q85→q80(최후) → LOD3 삼각형을 10,000에 붙임. 정점·인덱스 압축(①②③④⑤)은 이미 끝나 있어야 합니다.

#### 3.3 GATE 5(개인정보) 오탐 방지 — 사전 점검 절차

CI GATE 5는 매니페스트 전체 문자열에 정규식 `01[016789]-?\d{3,4}-?\d{4}`를 돌립니다. 문제는 **전화번호가 아닌 숫자열**이 여기 걸린다는 점입니다.

- 오탐원: 기사 URL의 ID(예: `…/archives/1163045`), 건물관리번호, 게시글 번호가 우연히 `01` + 7~8자리로 이어지는 경우.
- **사전 점검 3단계**(PR 오픈 전 필수):
  1. 매니페스트 전체를 위 정규식으로 **로컬 스캔**한다.
  2. 11자리 연속 숫자는 **출처를 확인**한다 — 전화번호면 삭제, 기사 ID/건물관리번호면 아래 처리.
  3. **`·` 분절 처리** 또는 **호스트만 남기기**: `_clean_url()`로 `https://www.yna.co.kr/` 처럼 호스트까지만 쓰고, 필요하면 숫자를 `1163·045`처럼 `·`로 끊거나 "기사 ID는 CI 개인정보 스캔 오탐 방지를 위해 생략" 주석을 답니다.
- 실적: 용산 50블록 중 6건(B14·B19·B20·B21·B25·B50)에서 오탐 발견 → URL 정리로 전건 PASS.

#### 3.5 `tools/validate_block.py` 7-Gate — 실행 로그 첨부 방식(중요)

- PR 오픈 전 **로컬에서 저장소 도구를 그대로 실행**합니다: `python tools/validate_block.py incoming/{폴더}/`
- GATE 1 스키마 · 2 확장자/실행코드 · 3 용량(파일 5MB/패키지 20MB) · 4 라이선스 · 5 개인정보 · 6 좌표 · 7 출처 도메인 → **ALL 7 CI GATES PASSED** 확인.
- 지시(PR #1165 §1-2)는 "실행 로그 파일을 PR 파일에 포함"이라고 하지만, **1 PR = 4종 규칙이 우선**입니다. 따라서 **로그 전문을 PR 본문의 코드블록으로 붙입니다**(파일 추가 금지). 로그가 없으면 "자체 PASS"로만 취급됩니다.
- 3AI가 표본을 재실행해 대조하므로 **로그를 편집·요약하지 마세요.** 실행 출력 그대로 붙입니다.

- **코멘트에 3종 캡처 명세(파일명·해상도·시점 설명)를 표로 등록**합니다. 캡처 PNG를 `incoming/` 폴더에 넣으면 4종 규칙 위반입니다.
