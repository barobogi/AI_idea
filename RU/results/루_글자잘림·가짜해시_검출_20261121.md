## 스크립트 1: text_box_detector.py

- `score_image()` 가 카드 경계(테두리 직선)를 찾고, 국소 대비 필터로 글자 잉크만 추출한 뒤 텍스트 라인 단위로 분석한다.
- **잘림(clip)**: CSS `overflow:hidden` 은 padding-box 경계에서 자르므로, 잘린 줄의 잉크는 테두리 2~9px 안쪽까지 닿는다. 경계 존에 끝이 닿는 4px+ 연속 잉크 런의 연속 행 블록을 검출. 정상 텍스트(패딩만큼 이격)와 라운드 코너 아크(행당 1~3px)는 걸리지 않는다.
- **넘침(spill)**: 박스 바깥 오른쪽/아래의 라인 잉크를 검출.
- **겹침(overlap)**: 배경과 다른 단색 요소(배지/리본/버튼)가 가린 라인 폭 비율 × 세로 점유율. 버튼 라벨 같은 요소 내부 잉크는 라인 잉크에서 제외하고, 완전히 가려진 줄은 줄 간격 리듬으로 추정한다.
- 반환: `{"scores": {"overflow_right", "overflow_bottom", "overlap"}, "flags", "bands"}`.

## 스크립트 2: hash_path_checker.py

- **추출**: md5/sha1/sha224/sha256/sha384/sha512(hex 길이 구분), 임의 길이 hex(8자+), git sha, UUID, bcrypt, sha-crypt, POSIX/Windows/UNC 경로.
- **형식 검사**: hex 길이, UUID version/variant 니블, bcrypt cost 범위, Windows 예약어(CON 등)·금지 문자, 구분자 혼용, 이중 슬래시. 형식 오류는 의심 1.0.
- **의심 규칙**: 플레이스홀더 토큰(deadbeef, 0123456789abcdef …), 동일 문자 연속, 연속 증감(0123…), 반복 블록, 최다 문자 z-점수; 경로는 템플릿 토큰(`<username>`), 플레이스홀더 세그먼트(/foo/bar, /path/to …), 상위 이동 `..`.
- 문서 점수 = 최고 의심 ×0.7 + 평균 ×0.3.
- **요청 범위대로 진위 대조는 하지 않는다** — 형식 + 의심 점수만 제공하고 실제 대조는 요청한 쪽에서 수행.

## 한계

- 스크립트 1: 테두리 없는 카드는 박스 검출이 불안정. 텍스트와 색이 거의 같은 장식 요소는 겹침으로 잡지 못함. 합성 분포 기준 평가라 실제 스크린샷과 차이가 날 수 있음.
- 스크립트 2: 형식이 맞고 자연스러운 가짜(임의 64자 hex)는 구분 불가 — 진위 대조 필요. 짧은 hex(8~16자)는 ID/색상 코드일 수 있음. 한글+공백이 섞인 Windows 경로(`D:\내 문서\파일`)는 끊길 수 있음.
