# 키링이 쓰레드_REF 1차 검토 표준 v1 (2026-11-14, 만복, 바로보기님 지시)

- 대상: 바로보기님이 올리는 쓰레드_REF 아이템(지도 외 관심 주제 전부 포함)
- 위치: `thread_ref/YYYYMMDD_<번호>_<주제>.pdf` 1개 + `thread_ref/thread_ref_registry.csv`에 한 줄
- 역할: 키링이는 **1차 정리**를 한다. 판정은 하지 않는다. 3AI가 위험 항목만 따로 검증한다.

## 1. PDF 구성 (5쪽 이내)
1. **원본 출처**: 링크, 작성자 핸들, 게시 날짜, KST 열람 시각. 열람 못 했으면 "열람 못 함, 사유 모름"이라고 쓴다. 로그인 창이 가린 화면은 캡처로 쓰지 않는다.
2. **핵심 주장 목록**: 번호를 붙여 한 줄씩. 원문 인용은 한 인용당 15단어 이내, 한 PDF에 5개 이내.
3. **사실 확인 칸**: 주장마다 확인한 출처 URL과 열람 시각. 직접 확인하지 못한 것은 "미확인"이라고 쓴다.
4. **제안(아이디어) 칸**: 사실과 분리한다. 제안을 사실처럼 쓰지 않는다.
5. **분류 태그**: `지도` / `학습` / `기타`, 그리고 `코드 있음` / `라이선스 있음` / `수치 있음` / `법적 주장 있음` 중 해당 것. (3AI가 이 태그로 검증 대상을 고른다)

## 2. 하지 않는 것
- "확인됨", "PASS", "100%" 같은 자체 판정 문구, 레지스트리의 자기 채점.
- 저장소에 없는 코드를 저장소 파일처럼 싣기. 직접 지은 예시 코드는 반드시 "예시 코드(원본에 없음)"라고 표시한다.
- 제3자 게시물·화면을 원문 그대로 복제하기(15단어 인용만).
- 글꼴 누락 PDF 제출. 제출 전 한글이 보이는지 직접 열어 확인한다.
- 첨부·다운로드 URL을 그대로 싣기. 서명·토큰이 붙은 임시 주소(`X-Amz-…`, `token=` 등)는 PDF·레지스트리에 넣지 말고 원본 페이지 주소만 적는다.

## 3. 공개 저장소 금지선 (AI_idea는 공개)
- 개인 위치·이동·사진 정보, 키·토큰·비밀번호.
- 지도 개발의 내부 결정(데이터 저장 방침, 약관 문의 내용, 비공개 저장소 구조).
- 이런 내용이 섞인 REF는 PDF를 만들지 말고 PR 댓글로 "비공개 처리 필요"만 알린다.

## 4. 제출 방식
- PR 1개에 PDF 1~3개. 제목은 `[REF] 날짜 주제`. 레지스트리 한 줄: 번호, 파일명, 원본 링크, 태그, 열람 시각.
- 답과 질문은 PR 댓글로. 3AI의 점검 결과도 댓글로 간다.

## 5. 3AI 후속 (참고)
- 위험 항목(수치, 라이선스, 약관, 법적 주장, 코드 실행)만 검증하고 나머지는 그대로 자산화한다.
- 학습 자산은 카탈로그 표에, 지도 후보는 후보 목록에 등록한다. 지도 후보 중 추가 검토가 필요한 것은 데스크탑 구글 드라이브로 옮긴다.

## 6. 목적 (바로보기님 11/14)
기존에 제미나이가 하던 REF 1차 분석을 키링이가 맡아 내부 자원(토큰)을 줄이는 것이 목적이다. 그래서 3AI는 위 5번의 위험 항목만 검증하고, 키링이의 정리를 다시 쓰지 않는다. 키링이는 정리의 완성도와 출처의 정확성에 집중한다.
