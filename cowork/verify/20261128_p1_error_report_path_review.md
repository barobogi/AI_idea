## 1. 현재 경로 실측 (2026-11-28 KST)
- 저장소: barobogi/korea-3d-map-site (공개). 이슈 기능 켜져 있음(has_issues=true), 지금까지 오류 신고 이슈 0건(전체 상태 조회 기준).
- 이슈 템플릿: `.github/ISSUE_TEMPLATE/error_report.yml` 1종. 필드: 장소/블록(필수), 무엇이 틀렸나요(필수, 설명에 "개인 정보는 적지 마세요" 안내), 근거 링크(공식 출처)(선택). 제목 접두사 "[오류] ", 라벨 error-report.

## 3. 후보 비교

### A. GitHub Issues 오류 신고 폼 (현재)
- 접수 단계: GitHub 계정 → 로그인 → 템플릿 선택 → 필드 3개 작성 → 제출
- 계정 불요: 아니오(실측: 리다이렉트로 확인)
- 구조화: 예(필수 2 + 선택 1, 라벨 자동 부여)
- 스팸 내성: 높음. 계정 자체가 진입 장벽이고 라벨로 일괄 관리 가능. 오픈 초반 스팸 리스크에 유리
- 알림·추적: 자동. 이슈 알림 구독, 공개 처리 이력
- 비용: 무료
- 개인정보: 제보자가 적는 내용 외 자동 수집 없음. 템플릿에 개인 정보 금지 안내 이미 포함
- 운영 부담: 낮음
- 약점: GitHub 계정이 없는 일반 방문자는 접수 불가. 국내 일반 사용자층에서 계정 보유율은 낮을 것으로 추정되나 통계 미확보(?)

### B. 이메일 접수 (mailto)
- 계정 불요: 예(이메일 앱만 있으면 됨)
- 구조화: 아니오(자유 서식). 필요 항목 안내 문구로 부분 보완
- 스팸 내성: 낮음. 공개 페이지에 주소를 노출하면 수집·스팸 노출. 주소 난독화는 완전한 대책이 아님(?)
- 알림·추적: 수동. 메일함에서 관리하며 처리 상태 추적·공개 이력 없음
- 개인정보: 답장을 위해 발신자 주소가 자연 수집됨
- 운영 부담: 중간
- 비고: 이 문서에서 실제 운영 주소를 지정하지 않는다(과제 금지 사항). 도입 시 운영자가 주소를 정해야 한다

### C. 웹 폼 서비스 (Google Forms 등 무료 폼)
- 계정 불요: 예(응답자 제출은 계정 불요, Google Forms 기준)
- 구조화: 예(필드 강제·필수 체크)
- 스팸 내성: 중간. 기본 스팸 방지가 있으나 무료 플랜별 수준·한도는 서비스마다 달라 개별 확인 필요(?)
- 알림·추적: 폼 서비스 기능 의존(응답 스프레드시트 집계 등)
- 개인정보: 응답 데이터가 제3자(구글 등) 서버에 저장된다. 공지·고지 문구에 수집 항목·보관·제3자 전송 안내 보강이 필요하며 이는 법률 검토 몫(?)
- 운영 부담: 낮음~중간
- 비용: 무료 티어 존재(한도·기능 확인 필요(?))
- 비고: 정적 사이트에는 자체 폼 백엔드가 없으므로 어떤 폼이든 제3자 서비스 의존
