# P3. 모바일 WebGL 검은 화면 원인 후보 (만복 @PO 과제, 기한 2026-11-29 12:00 KST)

작성: Fo (for barobogi) <barobogi79@fo.wajo.ai> · 2026-11-28

## 3줄 요약
1. 실측(2026-11-28): 구 페이지 3D 렌더러는 MapLibre가 아니라 Three.js다(vendor/three.min.js, b/11110/index.html에서 THREE.WebGLRenderer 사용). 원인 후보는 Three.js 기준으로 세웠다.
2. 이미 확정된 1순위 원인은 루 REQ134~136 분석의 'tiles_manifest.json 404 + 예외 미처리'다(재검증 아님, 인용). 모바일 추가 후보는 ①WebGL 컨텍스트 생성 실패 ②컨텍스트 소실(백그라운드 복귀·메모리 압박) ③고해상도 백버퍼 부담 ④구형 WebView의 WebGL2 미지원 순이다.
3. 진단은 기기별 원격 디버깅(Android Chrome USB, iOS Safari 웹 인스펙터)이 기본이고, 사이트 쪽 대책으로 window.onerror + webglcontextlost 리스너에 오류 안내 폴백 UI를 붙이는 것을 제안(?)한다. 문구는 UX 문구 4종 체계와 통일.

## 3. 원인 후보 (확정도 순)

### F1. tiles_manifest.json 404 + 예외 미처리 (확정, 루 인용)
모바일 무관이지만 흑화면의 직접 원인으로 먼저 수정돼야 한다. 모바일에서 재현이 더 잦게 보였다면 이 404가 모바일 경로에서만 나는지(경로·프록시 차이) 교차 확인 권장(?).

### F2. WebGL 컨텍스트 생성 실패 (높음)
- `canvas.getContext('webgl2'/'webgl')` 실패 시 Three.js가 오류를 던지고, 예외 미처리면 화면 갱신 없이 배경색(#0b111e)만 남아 검은 화면처럼 보인다.
- 해당 기기: 구형 안드로이드 WebView, WebGL 비활성 설정, 하드웨어 가속 꺼짐 브라우저.
- 확인법: 대상 기기에서 chrome://gpu (안드로이드는 개발자 옵션 원격 디버깅) 확인.

### F3. webglcontextlost — 컨텍스트 소실 (높음, 모바일 특이)
- 모바일은 메모리 압박·백그라운드 전환(다른 앱 사용 후 복귀) 시 WebGL 컨텍스트가 강제 소실될 수 있다(W3C WebGL 표준 이벤트).
- Three.js는 소실 이벤트를 받지만 복구(webglcontextrestored 이후 재초기화)는 사이트 코드가 해야 한다. 처리가 없으면 복귀 후 캔버스가 멈추거나 검게 유지될 수 있다(?).
- 대책(제안): webglcontextlost에서 기본 동작 방지 + 안내 UI 표시, restored에서 렌더러 재시작.

### F4. GPU 메모리 한도 초과 (중간)
- 3D 건물 fill-extrusion 스타일 지도는 블록·지오메트리 수가 많아 저사양 기기 GPU 메모리를 압박한다. 한도는 기기별로 달라 기준치를 못 정한다(?).
- 증상은 F3과 겹친다(컨텍스트 소실로 귀결).

### F5. 고해상도 백버퍼 부담 (중간)
- `setPixelRatio(window.devicePixelRatio)` 유지 시 고DPI 폰에서 백버퍼가 가로·세로 3배씩 커져 메모리·전력 부담이 급증한다. devicePixelRatio 상한(예: 2) 캡이 표준 완화책(제안).
- 사이트가 실제 어떤 pixelRatio를 쓰는지는 head·스크립트에서 미확인(?) — 저장소 코드 확인 필요.

### F6. iOS Safari 특이성 (중간, 미확인 다수)
- 캔버스 최대 면적·메모리 한도가 다른 브라우저보다 엄격하다는 사례 보고가 다수(?), 버전별로 다름.
- 백그라운드 전환 후 컨텍스트 소실 보고 다수(?) → F3 대책이 iOS에서 특히 중요.
- 진단: macOS의 Safari 웹 인스펙터로 원격 디버깅(맥 필요).

### F7. 데이터 절약 모드·프록시 차단 (낮음)
- 브라우저 데이터 세이버·통신사 프록시가 일부 fetch를 차단·변형할 수 있다는 가능성(?). F1의 404가 특정 네트워크에서만 재현되는지 교차 확인하면 함께 걸러진다.

## 4. 진단·대책 제안
1. 재현 환경 먼저 고정: 기기·OS·브라우저·네트워크·재현 절차를 오류 신고 양식에 추가하면 원인 분류가 빨라진다(P1 접수 경로와 연계).
2. 원격 디버깅: Android는 Chrome USB 디버깅, iOS는 Safari 웹 인스펙터. 현장 접수만으로는 콘솔 로그를 못 얻으므로 아래 3이 실용적.
3. 폴백 UI(제안): window.onerror + webglcontextlost 리스너에서 "화면을 불러오지 못했어요. 새로고침해 주세요." 안내를 띄운다. 문구는 UX 문구 4종(피망 PR #13346) 체계로 만복 검수 후 채택 권장.
4. F1 수정(404 경로)이 선행돼야 이후 원인 분리가 깨끗해진다.
