## 1. 응답 문구 5종 (해요체, 첫 응답용)

※ 모두 150자 이내. 문의에 처음 답할 때 쓰는 문장이다. 회신 채널은 접수된 이슈이므로 실제 주소·계정을 문구에 넣지 않는다. 볼드 부분은 문맥에 맞게 바꿔 쓰는 자리다.

### ① 오류 신고 접수
> 알려 주셔서 고마워요. 지도를 다시 확인한 뒤 결과를 이 이슈로 알려 드릴게요. 바로 고치지 못하더라도 확인 예정으로 남겨 둘게요. 근거 링크(공식 출처)를 더 주시면 확인이 빨라져요.
(약 92자)

### ② 데이터 정정 요청
> 정정 요청 주셔서 고마워요. 공식 출처와 비교해 확인한 뒤 반영 여부를 이 이슈로 알려 드릴게요. 반영이 늦어지는 경우 그 이유도 함께 말씀드려요. 근거 출처가 있으면 함께 알려 주세요.
(약 92자)

### ③ 저작권 문의
> 문의 주셔서 고마워요. 이 지도는 공공 출처 데이터를 사용했고, 사용한 출처와 라이선스는 사이트의 출처 문서에 정리돼 있어요. 문서에서 답을 찾지 못했다면 어떤 자료인지 알려 주시면 확인할게요.
(약 93자)
- 비고: 라이선스 판단·법적 결론은 하지 않는다. 출처 문서 위치만 안내하고, 추가 확인은 자료 확인 후 답한다.

### ④ 사용법 문의
> 사용법 문의 주셔서 고마워요. 지도는 한 손가락으로 끌어 움직이고, 두 손가락으로 벌려 확대할 수 있어요. 그래도 화면이 안 움직이면 어떤 화면에서 막혔는지 알려 주시면 확인해 볼게요.
(약 88자)
- 비고: 조작 설명은 현재 화면 동작 기준으로, 적용 화면과 다르면 수정이 필요하다(?) — 실제 UI 확정 후 대조 권장.

### ⑤ 제휴 문의
> 제휴 문의 주셔서 고마워요. 내용을 검토한 뒤 이 이슈로 답변 드릴게요. 검토에는 시간이 걸릴 수 있어요. 자료를 보내 주실 때는 개인 정보가 들어간 파일은 빼고 보내 주세요.
(약 84자)

## 2. 처리 흐름 (접수 → 확인 → 회신)

| 단계 | 방식 | 내용 |
|---|---|---|
| 1. 접수 | 자동 | GitHub Issues '오류 신고' 폼(또는 문의 채널)으로 접수. 플랫폼이 접수를 기록하고 알림. 템플릿 설명에 "개인 정보는 적지 마세요" 고정 안내(현행 error_report.yml 포함) |
| 2. 분류·확인 | 수동 | 라벨 분류(error-report 등) → 공식 출처 대조로 사실 확인 |
| 3. 처리 | 수동 | 반영 작업은 PR로 진행, 출처·확인일 기록(기존 기여 규칙 준수) |
| 4. 회신 | 수동 | 접수된 이슈에 코멘트로 결과 통보(위 문구 5종 사용). 폼을 도입하면 폼 접수분은 이메일 회신이 필요해(?), 이 경우 고지 문구 보강 필요 |
| 5. 기록 | 자동 | 공개 이슈로 처리 이력이 남아 추적 가능. 비공개 처리가 필요한 사안은 별도 정책 필요(?) |

- 첫 응답 기준(제안(?)): 접수 후 영업일 3일 내. 처리 완료까지 기한은 유형별로 다르게 둘 수 있으나 이 문서에서는 제안하지 않는다(?).
- 자동 요소는 접수 기록·알림뿐이다. 분류·확인·회신은 사람(운영자 또는 검수 담당 AI)이 한다. 접수 확인 자동 응답 메일은 GitHub 이슈에는 없으므로, 첫 수동 응답이 곧 확인 통보가 된다.

## 3. 개인정보 수집 최소화 원칙
1. 응답에서 추가 개인정보(이름·연락처·주소)를 요구하지 않는다. 소통은 접수 계정(닉네임)으로 한다.
2. 제보 내용은 공개 이슈에 남는다는 점을 접수 단계 안내로 커버한다(현행 템플릿 "개인 정보는 적지 마세요" 유지).
3. 문의 응답에 제보자 정보를 반복·복사하지 않고, 필요한 최소 내용만 인용한다.
4. 폼 서비스를 도입하면(P1 추천안) 수집 항목·보관 기간·제3자 전송 고지가 함께 필요하다(?).
